# 技术方案提示词

> 本文件记录生成《技术方案》所使用的完整提示词，按交付要求随 docs/ 一并提交。
> 使用方式：将以下全文作为指令发给 AI 工程师角色，即可复现本项目的开发过程。

---

你是一名资深 AI 应用工程师，帮我开发一套进出口代理单证一致性智能体系统。请严格按我给出的技术栈和约束执行，不要自行替换框架、不要引入我没要求的中间件。

【项目背景】
客户为上海外综服国际贸易有限公司（合成演练场景），业务链路五段：客户提供 → 单证检查 → 人工确认 → 委托作业 → 归档。现场痛点：发票、装箱单与订单的商品名称和单位不一致（f10）；客户更新装箱数量但商业发票版本未同步导致返工（f11，模拟异常）；现场习惯先群消息解决再补填表格，回填时间不等于发生时间（f13）；代理单证包无统一关联编号（f30）。演练基线"每月220票、每票42分钟"为虚构样本，不得作为设计依据或收益测算。需求取自业务发现报告 P0 三条：缺项清单+来源定位（f15/f42）、版本有效期+确认状态双条件判定（f24）、异常存疑一律进人工队列（f44）。

【系统定位】
本系统是"定位与提示"工具，不是审批或放行系统。核心交付物：一页缺项清单+对应来源位置（定位到原单据字段），供人工确认使用。智能体只承担字段一致性比对、版本双条件判定、差异来源定位、人工队列分派提醒；不承担审批、放行、覆盖原值、对外结论、自动申报归类或监管判断。验收口径：50票样本预设差异全部定位到原单据字段（f02），每条结果关联来源与人工复核记录（f42）。

【用户与权限】
一线单证专员（林亦舟角色）：可查询、看缺项清单、提交变更申请，不可确认放行；业务负责人（顾明岚角色）：唯一正式确认人（f22：一线可提交变更，正式确认由业务负责人完成）；审核与质量负责人（傅景角色）：人工队列出口，可暂停试点，查看全部审计记录（f44/f45）；流程协调员（唐映秋角色）：维护交接清单与确认链，只读+登记；系统模型角色：无审批权限，所有建议必须附带来源与人工复核入口（f14：系统建议不能覆盖原值或省略确认）。访问按授权范围控制，越权访问为零（f41）。

【技术栈，不许替换】
Python 3.11+；Web 框架 FastAPI（接口统一前缀 /api）；存储 SQLite 单文件（sqlite3 标准库，不用 ORM）；配置 PyYAML 全部集中于 config.yaml（模型地址、密钥占位符、字段白名单、链路节点）；LLM 仅经 OpenAI 兼容接口调用，模型名与地址从 config.yaml 读取；页面用 FastAPI + Jinja2 渲染缺项清单，不做独立前端；测试 pytest + httpx。不引入：Docker、Celery、MongoDB、Redis、消息队列、任何云服务 SDK。

【数据红线，硬约束】
只读边界：只对接脱敏只读导出数据源，不实现写回、外部消息、执行类接口（f32）；2) 人工队列：版本或关键字段无法确认一律进人工队列并暂停该票，禁止默认通过、禁止自动重试、不编造状态（f44/f35）；3) 双时间戳：更新同时记录业务发生时间与系统接收时间，过期来源不得覆盖已确认新版本（f34），回填时间不得当作发生时间（f13）；4) 字段口径：关键字段白名单=商品编码、数量、单位、金额、币种、版本，缺失值与未确认值必须区分标记（f31），质检问题记录保留原行（f33）；5) 版本判定：以版本有效期+确认状态双条件判定，作废记录保留原因，禁止按文件名猜最新版本（f24）；6) 审计留痕：记录谁查过、用哪个版本、提什么建议、谁确认，不得只留最终摘要（f45），留存原始版本、修订原因与确认人（f43）；7) 数据性质：全部样本标注"合成演练"，输出页固定声明"不代表真实授权、业务执行或客户验收"，保留期限与删除审批未定口径前不实现物理删除。

【代码规范】
每个函数写中文 docstring，说明入参、出参、失败时的行为。
关键业务逻辑（安全审查、权限校验、人工确认）必须写中文行内注释，说明为什么这么卡。
配置文件统一放 config.yaml，禁止把密钥、模型地址写死在代码里。
所有对外接口返回统一结构：{"ok": bool, "data": ..., "error": {"code": str, "msg": str}}

【交付要求】
每个阶段结束时，给我：① 变更文件清单；② 启动与自测命令；③ 一段能直接跑通的验证脚本；④ 你认为这一阶段最可能出问题的地方。不要给我解释性长文，我要能跑的代码。每行代码必须添加注释。
分阶段计划：阶段1 项目骨架（config.yaml、统一响应、五类表建表、只读导入器）→ 阶段2 核心比对（白名单校验、缺失/未确认区分、版本双条件、缺项清单+来源定位）→ 阶段3 流程红线（人工队列、确认接口、双时间戳、过期拦截）→ 阶段4 审计验收（全链路留痕、50票验收脚本、缺项清单页面）。

【文档交付】
技术方案输出为 docs/技术方案.md 与 docs/技术方案.docx 双格式；本提示词留存为 docs/技术方案提示词.md；测试 Harness 以 scripts/run_harness.py 一键跑批形式交付。

现在先不要动手写代码，用五句话复述你对项目的理解，并列出你打算先做哪三件事，等我确认。
